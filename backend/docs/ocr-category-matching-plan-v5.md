# OCR 部位自动选择 —— 实施方案 v5（最终版）

> **取代 v1~v4**。v5 基于 **19 张真实工单 × 双模式 OCR 实测** 重写。
>
> **核心结论反转**：现状「匹配率 90%」是**假象**。
> 真正的问题是 **模型幻觉 + 漏检 + 非喷漆项混入**，三者共同导致幅数算错。
> 方案方向随之改为：**让 LLM 只做 OCR，把归一化/过滤/匹配全部收回后端确定性代码**。

---

## 一、调研方法

| 项 | 内容 |
|---|---|
| 样本 | 19 张真实工单（HX×9 / ST×6 / FSXR×4），跨 2025-12 ~ 2026-08 |
| 模式 A（raw） | prompt 强制**原样照抄**图上文字，禁止改写/归一 → 看真实写法 |

| 生产库 | 3 门店 / 67 部位 / 5573 工单项 / 各店配置全量读取 |

## 二、致命发现：90% 匹配率是假象

### 2.1 baseline 数据（10 张图，模式 B）

| 图 | 图上实际行数 | 模型输出项 | 匹配 | 问题 |
|---|---|---|---|---|
| HX/2026-04 | 3 | 4 | 4/4 | 混入「更换」项 |
| HX/2026-05 | 2 | 1 | 1/1 | 漏 1 行 |
| ST/2025-12 | 4 | 4 | 4/4 | 喷漆行 5 个部位只输出 4 个；混入更换/修复/机修 |
| ST/2026-04 | 4 | 4 | 2/4 | 点漆、抛光未识别 |
| FSXR/2026-06 | 7 | 7 | 7/7 | **混入大量「更换」项** |
| FSXR/2026-08 | 4 | 3 | 2/3 | 漏 1 行；`前杠下饰板` ≠ `前后杠下饰板` 失配 |
| **HX/2026-01** | **31** | 18 | 18/18 | **≥6 项图上根本没有（幻觉）** |
| **HX/2025-12** | 5 | **1** | 0/1 | 严重漏检 |
| **FSXR/2026-02** | 6 | **1** | 1/1 | **喷漆项全漏**，输出的反是「更换」项 |
| ST/2026-03 | 7 | 7 | 6/7 | 混入大量非喷漆项 |

**合计 45/50 = 90% 匹配率 —— 但这个数字没有意义。**

### 2.2 三个真问题（按业务危害排序）

**🔴 1. 幻觉编造（HX/2026-01，大单）**

图上 31 行，模型输出 18 项，其中至少 6 项**图上完全不存在**：

```
模型输出但图上没有：机盖、前后杠半喷、下裙、包角、尾翼、拖车盖
```

图上有「发动机罩」（属维修项）、无「机盖」喷漆；「下裙/包角/尾翼/拖车盖」更是凭空出现。
**幻觉率 ≈ 33%，且这些项全部「匹配成功」，所以匹配率虚高。**

**🔴 2. 非喷漆项混入（普遍）**

例：FSXR/2026-06 图上只有 2 行喷漆，模型却输出 7 项，其中
`轮眉`、`挡泥板`、`保险杠下段` 全部来自 **`更换`** 行。
ST/2026-03 图上仅 1 行喷漆，输出的 7 项大半来自更换/修复/外修行。

**这直接导致幅数虚高** —— 是最严重的业务问题。

**🔴 3. 喷漆项漏检**

- HX/2025-12：图上 5 行 → 输出 1 项
- FSXR/2026-02：图上 6 行（含 2 行喷漆、3 个部位）→ 输出 1 项，且是更换项
  **喷漆项全漏，反而保留了不该计的项。**

### 2.3 根因

| 模式 | 召回 | 准确度 |
|---|---|---|
| **A（只照抄原文）** | **高**（31 行、7 行、6 行都完整输出） | 高（配件码、括号方位都读对） |
| **B（要求归一+匹配）** | 低（漏一半） | 低（幻觉 33%） |

> **结论：让模型「理解/归一」反而害了它。**
> 模型做 OCR 很准，做「业务归一化」会脑补。所以归一化必须收回后端。

## 三、三店工单格式实证

### 3.1 HX（比亚迪·宏现）—— 单店就有 5 种格式

| 月份 | 格式 | 示例 |
|---|---|---|
| 2025-12 | `动_部位（方位）_程度 工时 金额` | `喷漆_前门壳（右）_全喷 3.6小时 1.3 150.00 540.00` |
| 2026-01 | `配件码\编号 + 动_部位（方位）_程度 + 幅` | `WPWA0801001\10000864 喷漆_前门壳（右）_全喷 2.7` |
| 2026-02 | `配件码 \t 项目 \t 数字`（Tab 分隔） | `EQECAA9990021JT0\t喷漆_左后门门框\t0.2` |
| 2026-03 | `动_部位（方位）_程度` | `喷漆_前翼子板（右）_全喷` |
| **2026-04** | **动作后置、无下划线、顿号分隔** | `右前叶、右后包角喷漆 0.8` |
| **2026-05** | **动作后置** | `SA3EC9980002GH0 后杠、后盖（内外）喷漆 0 150 0` |

### 3.2 ST（盛通）—— 最规范

`动作：部位列表`，动作**前置**，部位间用 `,` / `，` / `.` 分隔：

```
更换：左后叶,左后三角玻璃,后杠,左后杠支架,左后尾灯支架,左后风
修复：左后门,后盖
喷漆：后杠,后盖,左后叶,左后门,左后门框
机修：换左后钢圈,四轮定位
钣金：左后门.左后叶.后杠
点漆：前杠（两边都有）
抛光：左前叶.左前大灯
```

### 3.3 FSXR（讯锐）—— 又不同

```
喷漆：右后杠（自费）              ← 冒号 + 括号是「业务标注」
喷漆：左A柱，左前门（内外）        ← 括号是「程度」
喷漆：前盖（内外），前盖铰链2个，左前杠，左前叶，左前叶支架2个   ← 部位带数量
①更换左前杠下饰板 17138197-00     ← 带圈序号
④喷漆:左前叶 前杠 前杠中饰板      ← 空格分隔多部位
```

> FSXR/2026-08 订单号是 `LGXCH4CD5S0825/00`（非 BYD 前缀），**存在第三套体系**。

### 3.4 格式总表

| 维度 | HX | ST | FSXR |
|---|---|---|---|
| 动作位置 | 前（`喷漆_`）或 **后**（`…喷漆`） | **前**（`喷漆：`） | 前（`喷漆：`） |
| 分隔符 | `_` / `:` / 无 / Tab | `:` `：` 或无 | `:` `：` |
| 多部位 | `、` | `,` `，` `.` | `，` 或 **空格** |
| 方位 | **括号**（右）或前缀 | 前缀（左后门） | 前缀（左前叶） |
| 程度 | `_全喷` `_中度` | 少 | `（内外）` |
| 干扰 | 配件码、金额列、工时 | 机修/钣金/外修行 | 配件行、精洗、序号 |

### 3.5 ⚠️ 括号内容有 4 种语义，不能当方位

| 示例 | 语义 |
|---|---|
| `前门壳（右）` | 方位 |
| `喷漆：右后杠（自费）` | **业务标注** |
| `左前门（内外）` | **程度** |
| `前杠下唇(裂纹)` | **损伤描述** |
| `点漆：前杠（两边都有）` | **补充说明** |

## 四、方案：LLM 只做 OCR，后端确定性处理

### 4.1 架构对比

| | 现状 / v1~v4 | **v5** |
|---|---|---|
| LLM 职责 | 读图 **+ 归一 + 匹配** | **只读图，输出原文** |
| 归一化 | 模型做（会脑补） | **后端别名词典** |
| 行过滤 | 无 | **后端按 action 白名单** |
| 部位匹配 | 模型给名字 → 精确查表 | **后端解析 → 词典 → 兜底模糊** |
| 幅数 | 模型 quantity | **系统按部位系数计算** |

### 4.2 处理流程

```
图片
 ↓ LLM（只 OCR）
{lines:[{lineNo, rawText, action, parts:[{body,side,degree}], qtyRaw}]}
 ↓ ① 行过滤（action 白名单）
 ↓ ② 部位拆解（多部位切分）
 ↓ ③ 归一化（去方位/去噪音/繁简/全角）
 ↓ ④ 别名词典匹配 → code
 ↓ ⑤ 程度耦合（半喷/里外 → 后缀部位）
 ↓ ⑥ 幅数 = 部位系数（不用模型给的）
工单项 + 置信度 + rawText 溯源
```

### 4.3 ① 行过滤（最高优先级，修正确性 bug）

| action | 处置 |
|---|---|
| 喷漆 / 补漆 / 点漆 / 喷 | ✅ 计入 |
| 抛光 | ⚠️ 计入但走 `isSpecial` 特殊项 |
| 修复 / 维修 / 钣金 / 机修 | ❌ 过滤（钣金工序） |
| 拆装 / 更换 / 外修 | ❌ 过滤 |
| 精洗 / 美容 / 贴膜 / 拖车 / 施救 | ❌ 过滤 |
| 含配件码（`HKHA-`、`SA3EC-`、`EM2E-`、纯大写字母数字） | ❌ 过滤 |

### 4.4 ③ 归一化规则

- 剥离序号前缀：`① ② ③` `1.` `2)`
- 剥离配件码与尾部数字列（`0 150 0`、`3.6小时 1.3 150.00 540.00`）
- 方位词剥离（**仅当不在部位词典中时**）：左/右/前/后/左前/右后…
- 括号内容：按词典判定是方位/程度/标注，非此二者则丢弃
- 全角→半角、繁→简、去空格

### 4.5 ④ 别名词典（从 19 张采样 + 67 部位表归纳）

**比亚迪体系（HX + FSXR）**

| 图上写法 | 系统部位 |

| 前/后门壳、前门、后门、左前门、右后门 | 车门 |

### 4.6 ⑤ 程度耦合

系统把程度做成**独立部位**（`车门` / `车门半喷` / `车门里外` / `车门内侧`）：

| degree | 拼接 |
|---|---|
| 半喷 | `body + "半喷"` |
| 里外 / 内外 / 全喷内外 | `body + "里外"` |
| 内侧 / 里面 | `body + "内侧"` |
| 全喷 / 中度 / 轻度 / 无 | 用基础部位 |

### 4.7 匹配主键

- **用 `code` 不用 `name`**（`下裙`、`倒车镜` 各重复 2 条）
- **code 大小写不敏感**（`skirt_only` / `SKIRT_SIMPLE` / `skirt_simple` 混用）
- `isSpecial=1` 的 9 项（全车/抛光类）单独分组，不进常规候选

### 4.8 兜底与置信度

后端解析失败时，才用模型的归一结果；仍失败则标「待确认」推 top3。
置信度映射同 v4 第四节（exact 0.98 / alias 0.95 / 词典 0.92 / 学习库 0.90 / 模糊 ≤0.85）。

## 五、prompt 改造

```
识别工单图片上的作业项目，逐行原样输出。
返回JSON: {"lines":[{"lineNo":1,"rawText":"该行原始文字","action":"喷漆","parts":["后杠","后盖"],"qtyRaw":"0 150 0"}]}
规则：
1. rawText 原样照抄，禁止改写、归一、拆分、纠错
2. action 取该行的作业类型（喷漆/补漆/点漆/抛光/修复/维修/钣金/机修/拆装/更换/外修/精洗/其他）
3. parts 为该行涉及的所有部位原文，用逗号分隔多个
4. 不要判断部位对应系统里的什么名称，原样输出即可
5. 配件编码行、金额行、工时行也要输出，action 填 "其他"
```

配套（v3 已识别）：`categoryIndex` 编号化需同时把 **cache key 加候选列表指纹**，否则跨店错配。

## 七、待确认业务规则（影响幅数正确性）

1. **修复/维修 是否计入幅数？** 我判断 ❌（钣金），但需确认。
2. **点漆 是否计入？** ST 有 `点漆：前杠（两边都有）`。
3. **抛光 怎么计？** 系统有 `抛光`/`抛光（单独项）` 两个特殊项。
4. **方位是否忽略？** 「左后门 + 右前门」算 2 幅还是合并 1 幅？
5. **幅数是否一律由系统按系数算？** 我建议是 —— 实证显示图上数字是工时/金额/个数，
   不是幅数（如 `喷漆_前翼子板（右）_全喷` 模型读出 qty=4.5，那是工时）。
6. **HX/2026-04 这类「动作后置」是否常见？** 需扩样确认（影响解析优先级）。

## 九、分期

| 期 | 内容 | 价值 |
|---|---|---|
| **P0** | **行过滤（action 白名单）+ 修静默丢弃** | 🔴 修幅数虚高 + 漏项，最高优先级 |
| **P1** | prompt 改造（只输出原文）+ 后端解析器 + 别名词典 | 🔴 消除幻觉、提升召回 |
| **P2** | 数据治理（name 去重 / code 归一）+ 候选按店裁剪 + 前端分级 | 🟠 提准确率 |
| **P3** | 校正闭环 + 学习库 + cache 指纹修正 | 🟡 越用越准 |
| **P4** | 图片池补识别 + 效果看板 | 🟡 |

**验收方式**：用现有 1959 张图做**离线回放**——
新解析器 vs 人工已录入结果，比对**精确率 / 召回率 / 幅数偏差**三个指标。
比人工标注基线集更快更准。重点看「幅数偏差」，那才是钱。
