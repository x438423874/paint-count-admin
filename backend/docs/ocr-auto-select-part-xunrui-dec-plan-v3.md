## 一、跨店实测基准（V3 核心依据）

### 1.1 方法

对三家门店各取 10 条「有图 + 有人工部位标注」的工单，
调用 `OcrService.recognizeWithTemplate(img, shopId, 'items')`，
按 `categoryId` 集合与人工标注对比，输出精确率与召回率。

> 与 V1/V2 的关键差别：**V1/V2 只统计了精确率**（识别到的里面有多少对），
> V3 首次同时统计**召回率**（人工标的里面识别出多少）。

### 1.2 结果

| 门店 | 模板部位数 | 精确率 | **召回率** | 匹配到模板外部位 | 识别 0 项的单 |
|---|---|---|---|---|---|
| **FSXR** 讯锐（比亚迪） | 45 | 66.7% (4/6) | **17.4%** (4/23) | 0 | 1/10 |
| **HX** 宏现（比亚迪） | 42 | 61.1% (11/18) | **27.5%** (11/40) | 0 | 2/10 |
| **ST** 盛通（别克/雪佛兰） | 42 | 75.0% (9/12) | **34.6%** (9/26) | **1** | 0/10 |

**三个直接结论：**

1. **精确率三店接近（61%~75%）** → 匹配逻辑本身没有门店特异性，架构可复用。
2. **召回率三店全部崩塌（17%~35%）** → 这是比精确率严重得多的问题，且 V1/V2 完全没有度量。
3. **盛通实测出现 1 例「匹配到模板外部位」** → V1 P0-2 描述的静默 0 幅数风险**不是讯锐独有**，P0 止血必须全店推行。
4. **但风险目前尚未落地**：附 B-4 巡检显示三店 `quantity>0 且 paint_count=0` **当前均为 0 行**。
   即静默 0 幅数还没真实发生过——P0 是**预防性止血**，不是救火，
   这也意味着现在做 P0 的成本最低（无需清洗历史脏数据）。

### 1.3 样本局限（执行前必须知悉）

- 这 10 条/店是随机取的，其中混有 Excel 导入工单（如 `B20260530001` 这类短工单号），
  **图片与工单未必一一对应**，召回率存在被低估的可能。
- 因此 §1.2 的召回率**只作为趋势信号**，不作为最终验收数字。
- **最终验收必须用 V2 的黄金集**（已审核、图片与部位人工确认对齐），并按 §2.1 同时统计召回率。
- 三店可建黄金集规模（有图 + 有部位工单数）：FSXR 784 / HX 874 / ST 791，样本充足。

## 二、V3 新增优化详述

### 2.1 【流程·阻断项】验收门补召回率

**V2 §2.2 现有验收门：**

> 项命中率 ≥ 85% 且模板外部位为 0

**问题**：这里的「项命中率」是精确率口径。以下两种结果都能刷过门禁，但业务价值天差地别：

| 情形 | 精确率 | 召回率 | 门禁 | 实际效果 |
|---|---|---|---|---|
| A | 90% | 85% | ✅ 通过 | 真正省事 |
| B | 90% | 20% | ✅ **通过** | 机器选的都对，但 80% 部位没识别出来，**用户仍要手工补全** |

**修订后的验收门（三店通用）：**

| 指标 | 口径 | 门限 |
|---|---|---|
| 精确率 | 识别命中 / 识别总数 | ≥ 85% |
| **召回率** | **识别命中 / 人工标注总数** | **≥ 60%（P1''）、≥ 80%（P2 目标）** |
| 模板外部位 | 匹配到但不在门店模板内 | **= 0** |
| 重复部位 | 同一单内 `categoryId` 重复 | **= 0** |
| 静默 0 幅数 | `quantity>0 且 paint_count=0` | **= 0** |
| 两轮一致性 | 同图跑 2 轮结果一致率 | ≥ 90%（见 §2.6） |

**黄金集回归脚本需同步输出**：漏识别榜（标注有、OCR 无 → 提示词问题）、
误识别榜（OCR 有、标注无 → 需人工确认是否图片真实存在）、未匹配原文榜（别名缺口）。

### 2.2 【P0''】OCR 输出去重与同部位合并

**问题**：实测 `BYDEGD061WRO260601003` 输出「叶子板、叶子板」。

**路径定性（V3.1 复核代码修正）**：`findDuplicateCategoryIds` 防重闸只覆盖
`create`（`work-order.service.ts:273`）、`update`（:419）、`merge`（:944）三条路径：

- **批量补录走 update，有防重闸**——重复部位导致整单更新报错（进 failed 明细），
  是 loud failure，**不会静默翻倍**；
- **真正静默翻倍的是 `quickCreate`（图片池自动建单 / 直接上传建单）——没有防重闸**，
  OCR items 直接 map 落库（:170-200），且它同时是 `?? 0` 静默零幅数路径（:186-187）。

**改法**：

1. `ocr.service.ts` `matchItemsToCategories` 返回前统一去重（上游治理，全部路径受益）：
   - 按 `categoryId` 分组；
   - 同组内 `quantity` **累加**、`newPartQuantity` 累加（而非覆盖）；
   - 累加后 `quantity` 超过阈值（建议 10）判定异常，**标记不自动采纳**交人工；
   - `matched=false` 的项不参与合并，单独进未匹配原文榜。
2. **`quickCreate` 补 `findDuplicateCategoryIds` 纵深防御**——
   V1 P0-2 本就要动 quickCreate 的 `?? 0`，一并修改。

> 不要简单「保留第一条」——同一部位在图片上占两行是真实场景（左前叶 + 右前叶），累加才是正确语义。
> 存量数据背书（V3.1 全库巡检）：历史 **0 例**同单重复部位，且「同部位一行、quantity 折叠」
> 是既有约定（存在 quantity=2 的存量行，如 `BYDEGD061WRO260328034` 车门×2）。

### 2.3 【P1''】部位粒度消歧

**问题**：实测 LLM 把「机盖」主动升级为「机盖里外」。
「机盖 / 机盖里外 / 机盖半喷 / 机盖内侧」是**不同部位、不同系数**，
V2 §2.3 只强调「半喷/里外/内侧不可剥离」，但没防住 LLM 主动升档。

**实测规模**（附 B-6）：全局部位表中带「里外 / 半喷 / 内侧 / 全喷」后缀的共 **11 个**——

```
前后杠半喷、后盖半喷、后盖里外、尾盖内侧、机盖内侧、机盖半喷、
机盖尾盖内侧、机盖里外、车门内侧、车门半喷、车门里外
```

基础部位（机盖 / 后盖 / 车门 / 前后杠）**每个都有 2~3 个变体**，
LLM 在候选列表里同时看到它们时极易选错档位——这不是边缘案例，是高频风险。

**改法**：

1. 把「里外 / 半喷 / 内侧 / 全喷」定义为**粒度敏感后缀**，构建「基础部位 → 变体集合」索引；
2. LLM 输出带粒度后缀而图片原文无对应证据时（依赖 §2.5 的 `rawText`），
   **降级为不带后缀的基础部位 + 标记 `needsReview`**，不自动采纳；
3. 前端预览表（V2 §2.5）里 `needsReview` 项高亮，人工一键切换变体；
4. 提示词显式说明：「只有当图片明确写了『里外』『半喷』等字样时才输出带后缀的部位，否则输出基础部位」。

### 2.4 【P1''】提示词模板化（跨店适配的关键）

**问题**：V2 §2.4 的提示词按「比亚迪 4S 工单」版式定制——
部位藏在「维修项目」表格自由文本里、顿号分隔、混有非喷漆项。
这套对宏现（同为比亚迪体系）大概率可用，但**盛通是别克/雪佛兰，版式与字段名不同，直接套用会失效**。

**改法**：

1. 把提示词拆成**固定骨架 + 门店可配片段**：

   ```
   固定骨架：输出格式、JSON 约束、候选编号选择、rawText/confidence 必填、勿编造
   门店片段（存 paint_shop.ocrConfig.ocrPromptHints）：
     - 部位所在区域（表格名 / 栏位名）
     - 分隔符约定
     - 需忽略的非喷漆项关键词
     - 该店特有的新件计数词（如"更换"）
     - 2~3 条该店真实文案的 few-shot
   ```

2. **默认片段**用比亚迪版（讯锐 + 宏现共用），盛通单独配一份；
3. 新增门店时只需填 `ocrPromptHints`，不改代码；
4. **缓存键必须带门店维度**：`sha256(buffer):mode:promptVersion:ocrConfigHash`
   （V2 §2.1 已提出「提示词按门店定制时 shopId 要进 key」，
   V3 明确这不是可选项而是**必选项**，且应取 `ocrConfig` 摘要以支持配置热改）。

### 2.5 【P0''】`rawText` 强制输出

**问题**：三店失配项里绝大多数是 `(空)`——LLM 认为不在候选列表就直接返回空，
既无 `matchedName` 也无 `rawText`。后果：

- V2 §2.5 的「未匹配原文聚合报告」（别名缺口清单）**拿不到数据**，会是空表；
- 失配后无任何二次补救手段；
- L2 模糊匹配拿到空串，无从计算。

**改法**（`llm-ocr.service.ts`，升为 P0'' 与止血同批）：

1. 提示词明确：**每个识别到的部位都必须输出 `rawText`（图片原文），无论是否匹配成功**；
2. 输出约束：`matchedName` 可以为空，但 `rawText` **不得为空**；
3. 后处理：`matchedName` 空而 `rawText` 非空 → 走 L0-L2 匹配（这正是 L2 模糊匹配的输入）；
4. 兜底：`rawText` 也为空时，记录一条 `unknown` 计数，纳入黄金集回归的「可观测性缺口」指标。

### 2.6 【流程】黄金集跑两轮，度量 LLM 抖动

实测同一张图（`BYDEGD061WRO251229012`）两次识别结果不同：

- 第 1 轮：`车门`
- 第 2 轮：`门拉手`

两次都不算错，但说明 `temperature=0.1` 下仍有随机性。含义：

- 黄金集**跑 2 轮**，取「两轮结果一致率」（建议门限 ≥ 90%）；
  ⚠️ 第二轮**必须绕过 OCR 缓存**（实现见附A），否则命中的是第一轮缓存，一致率恒 100%；
- 单轮达标可能是运气，两轮稳定才算真的达标；
- 进一步强化 V2 §2.5 两阶段预览的必要性——即使达标，单条结果仍可能出错，必须有人工确认环节。

### 2.7 【产品决策·已拍板 V3.2】定位重估：自动录入 → 辅助录入

**依据**：召回率 17%~35% 意味着，即使精确率做到 100%，
人工仍要为每条工单补全 65%~83% 的部位。

**建议的定位调整**：

| 维度 | 原定位（V1/V2） | V3 建议定位 |
|---|---|---|
| 目标 | 机器自动选对部位，人只审异常 | 机器给出候选，人做选择 |
| 交互 | 自动填充 + 低置信标红 | **部位候选条**（top3 一键勾选）+ 本店常用部位快捷条（V1 L3 频次） |
| 用户动作 | 审 100% 的结果 | 从「45 项下拉里找」→「3 个候选里点一下」 |
| 核心指标 | 精确率、召回率 | **平均每条工单的人工操作数**（最终业务指标） |
| 验收门 | 精确率 ≥85% | 精确率 ≥85% + 召回率 ≥60% + **人工操作数下降 ≥50%** |

> 这不是降低要求，而是让验收指标**对齐真实收益**。
> 召回率补齐后如果确实能上 80%，再回头升级为全自动不迟。

### 3.2 分层结论

**✅ 可直接全店复用（与门店无关）**

- P0-1 候选收窄到门店模板（三店模板 45/42/42 均需收窄，盛通已实测出现模板外部位）

- V2 缓存键版本号、黄金集回归框架、两阶段预览确认
- V3 去重合并、`rawText` 强制输出、验收门补召回率

**⚠️ 必须按店定制**

| 项 | 说明 |
|---|---|
| **提示词** | V2 §2.4 是比亚迪版式；盛通（别克/雪佛兰）需单独配。见 §2.4 模板化方案 |
| **别名词典** | 三店模板 `alias` 均为 0，`categoryAliasMap` 键数 29/34/29 各不相同，需各自整理并与内置字典合并 |
| **品牌映射** | 宏现 `fixedBrand=比亚迪`、盛通 `auto`、讯锐 `carSeries`——已有 `ocrConfig` 机制，新增门店沿用即可 |
| **部位粒度约定** | 「里外/半喷/内侧」变体在各店模板中的存在情况不同，需逐店核对（见 §2.3） |

### 3.3 推行顺序建议

1. **讯锐**（唯一有存量 76 条需求 + 已有 19 条黄金集）→ 先跑通全流程

## 附A：黄金集回归脚本要点（V3 修订）

```
输入：shopId, month, status=AUDITED（默认按月分层抽样 50~100 条/店，非全量）
for 每条工单:
    img = images[0]                       # 与生产批量补录同语义
    r1  = OcrService.recognizeWithTemplate(img, shopId, 'items')
    r2  = recognizeNoCache(img, shopId)   # 第二轮量抖动 ⚠️ 必须绕过缓存，见下
    label = { categoryId: quantity }      # 人工标注
    pred  = 合并同 categoryId 后的 { categoryId: quantity }        # 仅 matched=true
    统计:
      命中项     = |pred ∩ label|（quantity 容差 ±1）
      精确率     = 命中 / |pred|
      召回率     = 命中 / |label|              ← V3 新增
      误识别     = pred - label
      漏识别     = label - pred               ← 提示词问题
      重复数     = 合并前重复 categoryId 计数  ← V3 新增
      两轮一致率 = |r1 ∩ r2| / |r1 ∪ r2|       ← V3 新增
      未匹配原文 = matched=false 的 rawText 清单（喂别名回补）
      模板外部位 = pred 中不在门店模板内的     ← 应为 0
输出: 上述全部指标 + 漏识别榜 + 未匹配原文榜
```

> ⚠️ **两轮测试必须绕过 OCR 缓存（V3.1）**：`LlmOcrService` 内容寻址缓存 TTL 24h，
> 同进程内 r2 会直接命中 r1 的缓存——一致率恒 100%，度量的是缓存不是模型抖动。
> §2.4 的 `promptVersion/ocrConfigHash` 只让缓存「改配置后失效」，不解决「同配置跑两次」。
> 实现：第二轮 new 一个干净的 `LlmOcrService` 实例，或给 `recognize` 加 `skipCache` 参数。

> **抽样策略（V3.1）**：黄金集全量（784/874/791）× 2 轮 ≈ 4900 次 LLM 调用，且混入不同年代工单版式。
> 回归默认**按月分层抽样 50~100 条/店**；讯锐最终验收门另跑 **2025-12 的 19 条**（目标月份、版式一致、人工确认对齐）。

只读评估，不写库；缓存键带 `promptVersion + ocrConfigHash`，改提示词后重测即真实重算。

## 附B：跨店摸底 SQL

```sql
-- 1) 三店模板部位数 vs 全局部位数（确认收窄必要性）
SELECT s.code, s.name,
       (SELECT COUNT(*) FROM paint_standard_template_item WHERE template_id = s.standard_template_id) tpl_items,
       (SELECT COUNT(*) FROM paint_standard_template_item
         WHERE template_id = s.standard_template_id AND alias IS NOT NULL AND alias <> '') tpl_alias,
       JSON_LENGTH(s.category_alias_map) alias_keys,
       s.ocr_config
FROM paint_shop s;

-- 2) 各店存量「有图 + 无部位 + 未审核」（补录需求规模）
SELECT s.code, o.settlement_month, COUNT(*) c
FROM paint_work_order o
JOIN paint_shop s ON s.id = o.shop_id
WHERE o.status IN ('DRAFT','PENDING')
  AND EXISTS (SELECT 1 FROM paint_work_order_image i WHERE i.order_id = o.id)
  AND NOT EXISTS (SELECT 1 FROM paint_work_order_item t WHERE t.order_id = o.id)
GROUP BY s.code, o.settlement_month ORDER BY s.code, o.settlement_month;

-- 3) 各店可建黄金集规模（有图 + 有部位）
SELECT s.code, COUNT(DISTINCT o.id) c
FROM paint_work_order o
JOIN paint_shop s ON s.id = o.shop_id
WHERE EXISTS (SELECT 1 FROM paint_work_order_image i WHERE i.order_id = o.id)
  AND EXISTS (SELECT 1 FROM paint_work_order_item t WHERE t.order_id = o.id)
GROUP BY s.code;

-- 4) P0'' 验收：静默 0 幅数巡检（三店均应恒为 0 行）
--    2026-09-08 实测：三店均为 0 行 → 风险尚未落地，P0 属预防性止血
SELECT s.code, w.order_no, c.name, i.quantity, i.paint_count
FROM paint_work_order_item i
JOIN paint_work_order w ON w.id = i.order_id
JOIN paint_shop s ON s.id = w.shop_id
JOIN paint_item_category c ON c.id = i.category_id
WHERE i.quantity > 0 AND i.paint_count = 0;

-- 5) P0'' 验收：同单重复部位巡检（去重上线前后对比）
--    2026-09-08 实测：全库 0 行（防重闸 + 人工录入习惯共同作用）
--    V3.1 修正：分组键必须含 w.id——order_no 跨门店/月份不唯一，仅按 order_no 分组会误合并
SELECT s.code, w.order_no, i.category_id, COUNT(*) cnt
FROM paint_work_order_item i
JOIN paint_work_order w ON w.id = i.order_id
JOIN paint_shop s ON s.id = w.shop_id
GROUP BY w.id, i.category_id, s.code, w.order_no
HAVING cnt > 1
ORDER BY cnt DESC LIMIT 50;

-- 6) 部位变体（粒度）盘点：确认各店「里外/半喷/内侧」变体存在情况
SELECT c.name
FROM paint_item_category c
WHERE c.name REGEXP '里外|半喷|内侧|全喷'
ORDER BY c.name;
```
