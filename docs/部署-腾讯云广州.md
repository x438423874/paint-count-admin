后端更新发布（本机 → 服务器）：

```bash
cd backend && tar -czf /tmp/backend-src.tar.gz --exclude node_modules --exclude dist \
  --exclude logs --exclude uploads --exclude .env --exclude coverage .
scp /tmp/backend-src.tar.gz root@111.230.226.241:/root/
ssh root@111.230.226.241 'cd /opt/paint-count/backend && tar -xzf /root/backend-src.tar.gz \
  && export PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma \
  && pnpm install && npx prisma generate && pnpm build && pm2 restart soybean-admin-nest-backend'
```

数据库备份（手动）：

```bash
ssh root@111.230.226.241 'source /root/deploy-secrets.env && \
  docker exec mysql mysqldump -uroot -p${MYSQL_PASSWORD}-root --single-transaction soybean-admin-nest | gzip > /root/db-$(date +%F).sql.gz'
```

## 数据同步与备份（方案一：云端为准）

- **云端每日备份**：服务器 cron 每天 3:00 执行 `/root/backup.sh`，dump 到
  `/root/backups/db-YYYY-MM-DD.sql.gz`，保留 14 天（日志 `/root/backup.log`）。
  手动立即备份：`ssh root@111.230.226.241 /root/backup.sh`
- **本机拉取最新数据**：仓库根目录执行
  ```bash
  scripts/sync-from-cloud.sh          # 有确认提示
  scripts/sync-from-cloud.sh --yes    # 免确认
  ```
  会覆盖本机 `soybean-admin-nest` 库（表级重建导入）并把 `backend/uploads`
  镜像成云端状态（`rsync --delete`，本机多余图片会被删掉）。
- **约定**：生产数据只从云端录入（门店 H5 / 后台都在云上）；本机库仅作开发与查数，
  不要再往本机库录业务数据，否则会形成两份不一致的数据。

## 注意

- 图片经 macOS tar 传输会混入 `._*` AppleDouble 文件，重传后需
  `find /opt/paint-count/backend/uploads -name "._*" -delete`（本次已清理）。
- 服务器 pnpm 走 npmmirror，prisma engines 需 `PRISMA_ENGINES_MIRROR`（见上文）。
- H5 生产 API 地址在 `mobile-h5/.env.production`（VITE_APP_API_BASE_URL=/api），
  改后需重新构建并同步 `/opt/paint-count/www/h5`。
